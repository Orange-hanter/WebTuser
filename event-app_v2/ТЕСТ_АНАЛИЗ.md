# 🔍 Анализ ошибок E2E тестов

## ❌ Основная ошибка

```
Error: page.goto: net::ERR_ABORTED; maybe frame was detached?
```

## 🔎 Диагностика

### Проблема 1: Приложение перезагружается при проверке аутентификации

**Файл:** `src/App.tsx`
```typescript
const { isAuthenticated } = useAuth();

if (!isAuthenticated) {
  return <AuthFlow onAuthSuccess={() => window.location.reload()} />;
}
```

Когда тест заходит на `/` без токена:
1. Приложение загружается
2. Проверяет `isAuthenticated`
3. Получает `false` (нет токена в sessionStorage)
4. Вызывает `window.location.reload()`
5. Playwright теряет соединение

### Проблема 2: SessionStorage не сохраняется между загрузками

Тесты не подготавливают начальное состояние (token в sessionStorage) перед загрузкой приложения.

## ✅ Решение

### Способ 1: Использовать Context API для инициализации (РЕКОМЕНДУЕТСЯ)

```typescript
test.beforeEach(async ({ browser }) => {
  // Создаём контекст с инициализированным sessionStorage
  const context = await browser.newContext();
  
  // Инициализируем token ДО загрузки приложения
  await context.addInitScript(`
    window.sessionStorage.setItem('authToken', 'Bearer test_token');
  `);
  
  const page = await context.newPage();
  await page.goto('/');
  
  // Теперь приложение видит токен и не перезагружает
});
```

### Способ 2: Отключить перезагрузку в App.tsx для тестов

```typescript
// src/App.tsx
const handleAuthSuccess = useCallback(() => {
  if (process.env.NODE_ENV === 'test') {
    // В тестах просто обновляем состояние
    setShowApp(true);
  } else {
    // В production перезагружаемся
    window.location.reload();
  }
}, []);
```

### Способ 3: Использовать параметры URL для инициализации

```typescript
// http://localhost:5174/?test_mode=true&token=xxx
```

## 📝 Рекомендация

**Использовать Способ 1** (Context API), так как это:
- ✅ Наиболее надёжно
- ✅ Не требует изменений в production коде
- ✅ Полностью изолирует тесты
